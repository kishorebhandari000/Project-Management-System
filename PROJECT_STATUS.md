# Project Status Report — Project Management System (PMS)

Generated by reading the actual codebase (models, controllers, routes, every frontend
page, configs, and git history) — not from specs or assumptions. File paths are
repo-relative; `Backend_PMS/` is the API server, everything else at the root is the
Vite/React frontend.

---

## 1. Stack

**Frontend** (root `package.json`, name `@figma/my-make-file` — originated as a Figma
"Make" AI-generated scaffold, see [README.md](README.md)):
- **React 18.3** + **TypeScript**, built with **Vite 6** (`vite.config.ts`)
- **react-router 7** for routing ([src/app/routes.tsx](src/app/routes.tsx) — 45 unique routes)
- **Tailwind CSS 4** (`@tailwindcss/vite`) — hand-rolled utility classes site-wide; a
  full **shadcn/Radix UI** component library also exists at
  [src/app/components/ui/](src/app/components/ui/) (48 files) but is **unused** by any
  real page (confirmed by grep — nothing imports from `components/ui`)
- **socket.io-client** for realtime (chat, notifications)
- Assorted extra deps present but not wired into the app's own auth/data flow: MUI
  (`@mui/material`), `styled-components`, `next-themes` (dark-mode toggle, unused),
  `react-hook-form`, `recharts`, `react-dnd`, etc. — largely scaffold leftovers

**Backend** (`Backend_PMS/package.json`, name `backend-pms`):
- **Node.js** + **Express 4** ([src/app.js](Backend_PMS/src/app.js))
- **MongoDB** via **Mongoose 8**, connected in [src/config/db.js](Backend_PMS/src/config/db.js)
- **JWT** auth (`jsonwebtoken`), password hashing with `bcryptjs`
  ([src/middleware/auth.js](Backend_PMS/src/middleware/auth.js),
  [src/models/User.js](Backend_PMS/src/models/User.js))
- **socket.io** (server) for realtime push — messages & notifications
  ([src/utils/realtime.js](Backend_PMS/src/utils/realtime.js))
- **nodemailer** (SMTP) for transactional email (password reset, notifications, contact form)
- **File uploads**: `multer` + **Cloudinary**, with a **local-disk fallback** when
  Cloudinary credentials aren't set ([src/config/cloudinary.js](Backend_PMS/src/config/cloudinary.js))
  — in the current `.env`, **no Cloudinary credentials are configured**, so uploads
  currently land on local disk under `Backend_PMS/uploads/` (gitignored), served back via
  `app.use('/uploads', ...)` in [app.js:20](Backend_PMS/src/app.js#L20)
- **googleapis** (Google Sheets) for logging public contact-form submissions — also
  **not configured** in `.env` (no `GOOGLE_SERVICE_ACCOUNT_EMAIL`/`GOOGLE_PRIVATE_KEY`/`GOOGLE_SHEET_ID`),
  so this silently no-ops (caught and logged, not thrown) — see §7

**Auth model**: JWT bearer token in `Authorization` header, 3 roles (`admin`,
`supervisor`, `student`) enforced by [roleGuard.js](Backend_PMS/src/middleware/roleGuard.js)
per-route, plus per-resource ownership checks inside controllers (e.g. only a
submission's own supervisor can grade it).

**Hosting / deploy**: **none configured.** No Dockerfile, no `.github/workflows`, no
Vercel/Netlify/Procfile config anywhere in the repo. Both frontend and backend are
dev-only (`npm run dev`) — this is a local/dev project with no deployment pipeline.

**Database**: the configured `MONGO_URI` in `Backend_PMS/.env` points to a shared
MongoDB Atlas cluster (not a local instance).

## 4. Features PARTIALLY built

- **Tasks module has no frontend.** The backend (`taskController.js` +
  `taskRoutes.js`) is fully implemented and role-guarded, but **no page in
  `src/app/pages` calls `/api/tasks`** (confirmed by repo-wide grep) — there's no
  Kanban/task-list UI for any role. This looks like a backend feature that never got
  a frontend built for it, or was superseded by the Assessments flow.
- **Legacy Assessment fields are dead but still live in the API.**
  `Assessment` model still carries `submissionText`, `submittedAt`, `status`, `mark`,
  `feedback` ([Assessment.js:11-19](Backend_PMS/src/models/Assessment.js#L11-L19)),
  and `assessmentController.js` still exports `submitAssessment`
  (`PUT /assessments/:id/submit`) and `gradeAssessment` (`PUT /assessments/:id/grade`)
  that read/write those fields — but **no frontend page calls either endpoint anymore**
  (everything moved to `/api/submissions`). These routes are still reachable and would
  silently create parallel, never-displayed state if hit directly (e.g. via a stale
  bookmark, an old mobile client, or a curl script) — worth deleting or clearly
  deprecating.
- **`CreateAssessment.tsx` doesn't scope students to the chosen project.** The student
  dropdown is every student in the system
  ([CreateAssessment.tsx:33](src/app/pages/admin/CreateAssessment.tsx#L33),
  `GET /users?role=student`), not filtered by who actually has an approved allocation
  on the selected project. The supervisor field, by contrast, *is* correctly locked to
  `project.supervisor` and can't be mismatched. Backend doesn't validate the
  student/project relationship either.
- **Cloudinary and Google Sheets are both wired in code but unconfigured in this
  environment.** File uploads fall back to local disk (which works, but files won't
  survive a redeploy without persistent storage); contact-form Sheet logging silently
  no-ops. Both are "flip a few env vars" away from working, not missing code.
- **Dark mode**: CSS variables exist (`src/styles/theme.css` per
  [docs/week6-progress.md](docs/week6-progress.md)) and `next-themes` is installed, but
  nothing in the app toggles a `.dark` class — dependency present, feature absent.
- **shadcn/Radix `ui/` component library** (48 files) is fully present but entirely
  unused — every real page is hand-rolled Tailwind instead.

## 7. Known bugs / broken things

1. **Mixed package managers, currently present, previously caused a full outage.**
   Both the repo root and `Backend_PMS/` have **all three** of `package-lock.json`,
   `pnpm-lock.yaml`, and `pnpm-workspace.yaml` checked into git simultaneously. This
   exact combination broke `npm install`/the dev server once already (`git log`:
   `dfd7fdd "Fix duplicate route registration, repair broken lockfile, remove orphaned
   pnpm config"` removed the pnpm files) — but a later commit, `217f47d "pnpm update
   (myside)"`, **re-added them**, and they're still tracked on `main` today
   (`git ls-files | grep pnpm` confirms both root and `Backend_PMS/pnpm-lock.yaml` /
   `pnpm-workspace.yaml` are currently committed). This is a live regression risk, not
   a historical footnote.
2. **`CreateAssessment.tsx` can assign work to unrelated students** — see §4; the
   student dropdown isn't scoped to the selected project's allocations, so an admin
   could (accidentally or not) assign an assessment to a student with no relationship
   to that project.
3. **Orphaned legacy assessment-grading endpoints** (§4/§6) are still live and would
   silently diverge from what the UI shows if ever hit directly.
4. **Stray `Backend_PMS/assesment` file** (§6) — harmless but should be deleted; its
   presence/naming (no extension, wrong spelling, wrong location) suggests an accidental
   commit rather than an intentional artifact.
5. **File uploads aren't durable in this environment.** With no Cloudinary
   credentials configured, submission/project files persist only on local disk
   (`Backend_PMS/uploads/`, gitignored) — they won't survive moving to a new machine or
   a real deploy without either configuring Cloudinary or provisioning persistent
   storage.
6. **No production/dev environment flag gating anything sensitive** — e.g.
   `errorHandler.js` only hides stack traces when `NODE_ENV === 'production'`
   ([errorHandler.js:9](Backend_PMS/src/middleware/errorHandler.js#L9)), but nothing in
   `Backend_PMS/package.json`'s `start`/`dev` scripts ever sets `NODE_ENV`, so stack
   traces are likely exposed in every environment this has actually been run in so far.
7. **Known, deferred, pre-existing `npm audit` findings** — per
   [docs/week6-progress.md](docs/week6-progress.md): 5 findings on `Backend_PMS` (1
   low, 4 high) as of the last time someone looked; not re-verified for this report
   (would require running `npm audit`, a live network call I didn't make so this
   report stays to static code reading — flagging as something to re-check).
8. **~552KB single-chunk production JS bundle**, per the same doc — Vite warns on
   this; no route-level code-splitting yet.

almost every endpoint, thoughtful edge-case comments (stale-snapshot bugs pre-empted,
orphan-file cleanup on failed uploads, graceful Cloudinary fallback), and a genuinely
complete data model. The frontend matches it: I could not find a single page still on
mock/hardcoded data across all three roles. What's missing is less "unbuilt features"
and more "production hardening" — tests, deploy config, and cleanup of a few
now-orphaned code paths.

1. **Resolve the pnpm/npm lockfile conflict for good** (§7.1) — this has already caused
   one full outage and is still present on `main`. Decide on one package manager,

   `.gitignore` rule or a pre-commit check so it can't silently come back a third time.
2. **Add a real test suite**, even a minimal one — there is currently zero automated
   coverage on a codebase with meaningful business logic (allocation seat-counting,
